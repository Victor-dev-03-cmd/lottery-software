━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Business: Ajith Rohana Enterprise — a Sri Lankan NLB/DLB lottery ticket
distributor operating under Nimalsiri Enterprises.

The software manages the full lifecycle of lottery ticket distribution:
  - Purchasing tickets from Nimalsiri Enterprises (supplier)
  - Issuing tickets to agents on credit
  - Collecting payments from agents
  - Recording winning tickets
  - Returning unsold tickets
  - Financial reporting (profit/loss, commissions, daily collections)

The system has TWO components:
  1. Desktop Application  — Windows & Linux, runs offline with local SQLite DB
  2. Mobile Companion App — Android Flutter app, scans tickets in the field

── SERVICES ─────────────────────────────────────────────────────────────────

session_service.dart  — Desktop connection & data transfer
  Two modes:
    LAN Direct: HTTP POST to http://IP:7423/api/v1/scan
                Health check every 20s via GET /api/v1/health
    Relay:      WebSocket to Go relay server
                Auto-reconnect with exponential backoff
  joinFromQR(qrData):
    Parses: lottery://pair?host=IP:7423  (LAN direct)
            lottery://pair?session=X&relay=ws://HOST  (relay)
            lottery://IP:7423  (legacy format)
  sendTicketData(ticket, action):
    Sends to /api/v1/scan with full ticket payload

qr_parser.dart        — NLB/DLB ticket QR code parser
  Detection logic:
    NLB: contains 'nlb.lk' OR game name in _nlbNames map
    DLB: contains 'dlb.lk' OR game name in _dlbNames map
    Fallback: contains() check if startsWith() misses (encoding headers)

  NLB format: "SUBA DAWASAK 0455 2026/10/13 088004550203409 ..."
    Extracts: game name, draw number, draw date, serial (10-16 digit token)
    Fallback: regex scan for 9-16 digit sequence

  DLB format: "SASIRI 1143 2026.10.13 1143 - 23456 - 2 - 15 ..."
    Extracts: game name, draw number, draw date
    Serial: 4-group regex (\d{3,6}-\d{2,12}-\d{1,4}-\d{1,4})
    Fallbacks: 3-group, standalone 5-14 digit, contiguous regex scan

  barcodeStart getter in TicketData:
    NLB: serialNumber as-is (numeric)
    DLB: strip all dashes/spaces (1047-672103968-5-01 → 1047672103968501)

7. MOBILE ↔ DESKTOP REAL-TIME SYNC FLOW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Step 1: Pairing
  Desktop: Settings → Mobile App → shows QR code (lottery://pair?host=IP:7423)
  Mobile:  Settings → Scan Desktop QR → connects to desktop HTTP server
  Result:  sessionService._desktopHost = "192.168.x.x:7423"

Step 2: Scanning a ticket
  Mobile: Camera scans NLB/DLB ticket QR code
  Parser: Extracts game, draw, date, barcode
  Form:   Auto-fills Purchase Details (barcode start, draw no, date)
  Badge:  "Sent to Desktop" shown on success

Step 3: Push to Desktop
  Mobile HTTP POST → http://IP:7423/api/v1/scan
  Headers: Content-Type: application/json
           x-api-key: LOTTERY_COMPANION
  Body: { game_name, draw_number, draw_date, barcode_start, board, raw_qr }

Step 4: Desktop receives
  Rust handler receives POST → emits Tauri event "mobile:ticket"
  React (Purchases.tsx) listener fires:
    - Dedup check: same key within 2.5s → discard (prevents duplicates)
    - If form closed: opens New Purchase form, pre-fills first row
    - If form open: fills last empty row, adds new empty row
  Flash notification: "📱 Game Name · Draw XXXX received" (3.5s)

Step 5: User completes the purchase
  User fills in: barcode_end (scan end ticket), qty, price
  Clicks "Save Purchase" → saved to SQLite inventory_batches

    "platforms": {

      "linux-x86_64":   { "url": "..._amd64.AppImage.tar.gz", "signature": "..." }
    }
  }

CRITICAL: Tauri updater requires SPECIFIC archive formats:
  Windows: _x64-setup.nsis.zip   (NOT the plain .exe installer)
  Linux:   _amd64.AppImage.tar.gz (NOT the raw .AppImage)

GitHub Actions workflow (.github/workflows/release.yml):
  Job 1: verify-version  — Confirms git tag == tauri.conf.json version
  Job 2: publish-tauri   — Builds Windows + Linux installers
  Job 3: ensure-manifest — Creates updater archives from installers,
                           signs if TAURI_SIGNING_PRIVATE_KEY is set,
                           uploads latest.json

Signing key: minisign keypair
  Public key in tauri.conf.json: plugins.updater.pubkey
  Private key: TAURI_SIGNING_PRIVATE_KEY (GitHub secret)
  dangerousInsecure: true currently set (skip verification until secret added)
